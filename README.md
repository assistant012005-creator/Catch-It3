# Catch-It / Домой

Mobile-first прототип планировщика маршрута Вешних Вод → Катуар и обратно. Только фронтенд; демонстрационные расписания не являются реальными данными и не должны использоваться для поездок.

## Запуск

- Windows: запустите `start_preview.bat` (нужен Python 3). Сервер раздаёт корень репозитория, начиная с порта 8080, и открывает `/web/index.html`.
- Или откройте `web/index.html` напрямую: классические скрипты и встроенная копия конфигурации поддерживают `file://` без CORS-запросов.
- Другие системы: `python3 preview_ui.py`.

В браузере выберите направление, время и автобус. Иконка ◐ переключает три темы, кнопки у маршрута — три компоновки. Нажмите «Настроить» на пересадке для калибровки. QA / Chaos Simulator содержит сценарии и инъекции сбоев. Темы и вид сохраняются локально. При HTTP-запуске service worker сохраняет оболочку для повторного открытия офлайн; конфигурация в этом случае берётся из встроенной копии.

## Устройство

`config/` — источник демонстрационных расписаний, профиля и подсказок. `web/js/config_fallback.js` — встроенная копия для автономного запуска; при изменении JSON нужно обновить и её. `store.js` разделяет состояние, адаптер расписаний и независимый от DOM движок `RouteEngine.calculateRoutePlan`. Рендерер использует RoutePlanDTO. Никаких сетевых запросов к Яндексу и серверной логики нет. Расписание повторяется ежедневно, времена условно московские; время на часах при старте берётся из локального времени устройства. Обратный маршрут использует модель среднего ожидания автобуса и расписание МЦК (или половину интервала при сбое).

`FREE_OPTION` — вероятностная попытка с запасом от −30 до +90 секунд, а не гарантия посадки; при неудаче остаётся спокойный поезд. Буферы посадки применяются при выборе надёжного рейса. Точные рейсы, длительности и доступность нужно проверять у перевозчика.

Проверка расчётов: `node tests/engine.test.js`.
